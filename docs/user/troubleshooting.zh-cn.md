# 故障排查

排障时先确定问题位于哪一层：硬件枚举、端口发现、AT 通道、数据会话，还是 OpenWrt 路由和防火墙。页面上的单一状态不能替代分层检查。

## 扫描不到模组

优先检查：

1. 模组供电是否稳定，USB 或 PCIe 链路是否枚举。
2. 串口和数据接口驱动是否加载。
3. USB `VID:PID` 和 interface number 是否符合端口规则。
4. 模组是否切换到了不包含 AT 或数据接口的 USB composition。
5. `modem_scand` 是否运行，扫描队列是否接受任务。

```sh
logread -e modem_scand
modem_scanc status
```

不要通过把所有 tty 都强制当作 AT 端口来掩盖问题。诊断口可能对部分命令响应，却不适合作为长期控制端口。

## AT 命令响应残缺或超时

常见原因是多个程序同时读取同一串口。停止其他模组插件、串口终端或模组 WebUI ATD 后重试。确认 QModem 的 `use_ubus` 设置与 `ubus-at-daemon` 使用方式一致。

如果只有特定命令失败，记录原始请求、完整十六进制响应、终止标志和超时时间；不要只截取页面中的一行错误。

## 能发 AT，但不能拨号

检查：

- SIM 已就绪并完成网络注册。
- 当前拨号协议与数据接口驱动一致。
- APN、PDP 类型和认证参数正确。
- 模组没有被锁在当地不可用的频段或小区。
- QMI/MBIM/MHI 控制设备没有被另一进程占用。
- 拨号日志中是否存在运营商拒绝、无服务或超时。

## 拨号成功但不能访问网络

把问题拆成地址、路由、DNS、防火墙四部分：

```sh
ip address show
ip route show
ip rule show
nft list ruleset
cat /tmp/resolv.conf.d/resolv.conf.auto 2>/dev/null
```

先用 IP 地址测试连通性，再测试域名。如果 IP 可达而域名失败，重点检查 DNS；如果接口有地址但没有正确路由，检查 metric、多 WAN 和策略路由；如果路由正确但 LAN 客户端失败，检查防火墙 zone、转发和 NAT。

## 长短信无法正确拼接

部分运营商或模组提供的短信时间戳、reference ID 不稳定。QModem 的拼接结果因此可能错误。这不是简单增加等待时间就能解决的问题。反馈时应提供脱敏后的 PDU、分片顺序、reference ID 和模组型号。

## 锁频或锁小区后无服务

立即恢复厂商定义的自动频段或自动选网模式。如果无法恢复，执行模组软重启或断电重启。不要把其他型号的解锁命令直接用于当前模组，即使它们来自同一厂商。

## 提交问题前收集信息

至少提供：

- 路由器型号及供电方式。
- OpenWrt/ImmortalWrt 版本、target、内核版本。
- QModem 版本和安装的软件包列表。
- 模组完整型号、固件版本、USB 或 PCIe 连接方式。
- USB `VID:PID`、interface/driver 映射或 PCIe/MHI 枚举信息。
- 使用的 AT 端口、数据接口和拨号协议。
- 可重复的操作步骤、期望结果和实际结果。
- 相关 `logread`、拨号日志和脱敏后的 AT 响应。

公开前删除或替换 IMEI、IMSI、ICCID、手机号、短信正文、APN 凭据、公网地址和设备密钥。反馈包加密只能保护传输内容，不能替代提交者对接收方和数据范围的确认。
