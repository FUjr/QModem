# QModem 分支与发布策略

## 分支职责

| 分支 | 定位 | 允许内容 | 标签 |
| --- | --- | --- | --- |
| `main` | develop、默认分支、社区测试线 | 新功能、不紧急更新、regular fix，以及紧急修复的开发版本 | `vX.Y.Z-rc.N` 或 `vX.Y.Z-beta.N` |
| `stable` | 稳定维护线 | hotfix、紧急需求、维护者明确批准的已验证合入 | `vX.Y.Z` |

预发布标签只能指向 `main`，稳定标签只能指向 `stable`。CI 会检查标签提交是否属于
对应分支，错误来源会直接阻断发布。

## 开发流程

feature 分支从 `main` 创建，完成测试后合并回 `main`，再交给社区测试。经过一段验证期
后，只有维护者明确指定的功能才合入 `stable`。当前远端已删除 `master`，因此不能把
“从 master 创建 feature”当作现行可执行步骤；若恢复该分支，必须先确认它与 `main`、
`stable` 的职责关系。

变更分类如下：

1. 紧急需求同时进入 `main` 和 `stable`。
2. 新功能、不紧急更新和 regular fix 只进入 `main`。
3. hotfix 同时进入 `main` 和 `stable`。
4. 新功能与紧急需求冲突时，暂停合并并请求维护者决定取舍。
